# Plan — typed `Field.type` + typed `interfaces` in the plugin model

Status: **implemented** (`./gradlew build` green: all modules compile, 53 test classes
pass incl. the fixtures' protoc round-trip, spotless/Checkstyle/EP/NullAway/-Werror).

## KTD (implementation decisions, 2026-07-19)

- **KTD1 — `Field.type` is the field's Java type as decided by the loader**, mirroring the old
  writer mappings exactly: primitive for non-presence scalars, `java.lang` boxed for presence,
  `List<T>`/`Map<K,V>` for repeated/map (boxed element/keys/values), the WKT's native Java type
  (timestamp→`Instant`, …), the referenced record/enum's `Named` (pkg + enclosing chain from
  `FileTable`), `java.lang` `String`/`Object` for string/unresolvable. `typeUrl` stays as the
  wire/WKT-dispatch token.
- **KTD2 — oneof value records render the boxed reference form** (`TypeRefs.boxed(member.type())`)
  so the record's `value()` accessor covariantly overrides `Unwrapable<Object>#value()` — a
  primitive return (`int`) would not compile. (Diverges from the old bytes→`Bytes` boxed mapping
  only for a oneof member of `bytes` type, which now renders `byte[]`; no fixture exercises it.)
- **KTD3 — nested type references are emitted bare inside their own enclosing class**
  (`TypeRefs.inScope`): the loader's `Named` for a nested type carries the enclosing chain
  (`Sample.Fixed`), but a `@Nullable` (TYPE_USE) annotation cannot apply to a qualified type name
  under javac, and a nested member is in name scope inside its own enclosing record anyway.
  `inScope` strips the enclosing chain when the reference's outermost enclosing type is the
  referring record and both share the declaring package; all other references keep the chain
  (the two-phase collector then renders short names in-package, imported out-of-package).
- **KTD4 — the WKT registry is itself typed.** `WellKnownTypes.Entry.javaType` is now `@Nullable TypeRef` — shared `TypeRefs` constants (`INSTANT`/`DURATION`/`FIELD_MASK`/`EMPTY`, the codegen boxed constants, `TypeRefs.BYTES`), null only for `DYNAMIC_UNSUPPORTED` entries. The loader returns it directly instead of `TypeRef.of(requireNonNull(String))`, and `WktSourceMapping` renders from it instead of a `String → shortName → TypeRef` round-trip (a string-era vestige the KTD1 work left behind); the CodeGenerator typeResolver lambda keeps its old FQN-string behavior for the supported set.

## Context

The model layer (and the writers) currently carry proto **string type URLs**
(`"int32"`, `"bijnagte.recordbuf.fixtures.Color"`) and **string FQN interfaces**
and re-derive Java types ad-hoc at ~10 writer sites. The user asked to replace
these strings in the model with the **`TypeRef` that represents the class each
field comes from** (reusing `bijnagte.recordbuf.codegen.source.TypeRef`), and to
capture the `recordbuf.java_interfaces` option as **fully typed classes**
(`List<TypeRef>`), not strings. A prior session attempted this with a *model*
`TypeRef` class (in a dirty worktree); that work was **abandoned** — the plan
reuses the existing codegen `TypeRef`, with primitives supported via the new
`TypeRef.Primitive` variant.

## Changes

1. **`codegen …source/TypeRef`** — add `Primitive` variant
   (`int/long/float/double/boolean`, `short`/`char`/`short`-style rendering)
   and a static `TypeRef.of(String fqnOrPrimitive)` that maps known primitive
   keywords to `Primitive` and anything else to `Named` (pkg = up to last dot).
   (Additive; existing `of` keeps `Named` semantics.)

2. **`model/Field`** — add component `TypeRef type` (after `typeUrl`).
   `typeUrl` stays (wire/WKT/dispatch token). `type` = the field's **Java**
   type: primitive/boxed per presence, `List<T>`/`Map<K,V>`, WKT's native
   Java type, or the referenced record/enum's `Named` (pkg + enclosing from
   `FileTable`).

3. **`model/Message` + `model/Enum`** — `interfaces: List<String>` →
   `List<TypeRef>` (parsed via `TypeRef.of`).

4. **`model/FileTable`** — remember the per-file `javaPackage` so
   cross-file `javaFqn` → `javaPackage` resolution works
   (`javaPackageOf(protoFqn)`), for building `Named` types outside the file
   currently being loaded.

5. **`model/ModelLoader`** — build `Field.type` (mirrors the writers' existing
   mapping exactly so generated bytes stay identical) and the typed interfaces.

6. **Writers consume `type` instead of re-deriving:**
   - `RecordSourceMapping`: `scalarComponentType` → `f.type()`; oneof member
     `valType` → `member.type()` (WKT member branch keeps its entry-driven
     loud failure); implements clause → `m.interfaces()` (TypeRefs); drop the
     `typeResolver` parameter from `toSourceWithCodec` (the codec gets everything
     from `f.type()`).
   - `CodecSourceMapping`: decode locals for scalar/map/repeated/message/enum →
     `f.type()`; message/enum **codec refs** → `f.type().sub("<Short>Codec")`;
     oneof refs likewise; drop the `typeResolver` parameter.
   - `EnumSourceMapping` / `InteropSourceMapping`: implements refs / sibling
     refs → `f.type()` / `m.interfaces()`.
   - `CodeGenerator`: delete the `typeResolver` lambda.
   - `WktSourceMapping`, `Avro*`: unchanged (entry/token driven; the WKT
     `requireNonNull(javaType)` loud failure for dynamic WKTs is preserved).

7. **Tests** — construction helpers (`RecordSourceMappingTest.field`,
   `AvroConverterSourceMappingTest.scalar`, …) take/derive a `TypeRef`;
   resolver-arg call sites drop the arg; expectation strings unchanged for the
   same-package fixture family. `ModelLoaderTest` gains coverage for the new
   mapping (primitives, optional-boxed, repeated/map, message/enum `Named`,
   WKT native, typed interfaces).

## Invariants

- Wire numbers, `typeUrl` token, WKT dispatch, defaults, and oneof semantics
  are untouched — `type` is a *presentation* concern only.
- Generated fixture output expected **byte-identical** except for cross-package
  references (which the old bare-short-name strings got *wrong*; a diff there is
  a fix, to be reviewed when it appears).

## Follow-ups

- **In-scope rendering (LANDED, a943a74).** `SourceRenderer` carries the lexical scope
  chain (outermost first) at every `ci.use(ref, scope)` site; `TypeRef.Named` resolves
  scope-aware. The writer-side `inScope` helper is deleted — the rule is a renderer
  concern.
- **Writers emit typed references (LANDED, a943a74).** Codec references via
  `codecRef(f)` (nested `<Element>.<Element>Codec`; a repeated field's element is its
  generic argument, NOT the `List` wrapper), oneof locals/wrappers via `recordRef.sub(...)`
  chains, `permits` resolved scope-aware, `decode()` drops its hand-built `pkg`. Fixes a
  latent ungenerated-import for cross-package message fields.
- **Declaring specs still carry `String` names (DEFERRED — Layer 2).**
  `ClassSpec`/`RecordSpec`/`EnumSpec`/`InterfaceSpec.name` would switch to `TypeRef`
  (~54 construction sites across five writers) for full declared-type identity; changes
  no output on its own. Re-scope when cross-file declarations make it earn its keep.
- **WKT fields still carry the WKT FQN in `typeUrl`** (KTD2); switching `Field.typeUrl`
  to a `TypeRef.Named` is a separate model decision.
- **In-scope drop rule (the subtle bit).** A leading enclosing segment is dropped only
  when it is in scope AND the reference shares the scope's package: nested members render
  bare (`Sample.Fixed`, `Compat.Choice`); a same-named top-level sibling stays qualified
  (`Item.ItemCodec`, never `ItemCodec` — a top-level class's nested members are only
  reachable via the qualifier).
- **Verification.** `./gradlew build` green; regenerated output byte-identical to the
  pre-refactor baseline (committed fixtures show no diff; the oneof fixture — permits,
  oneof locals, `Sub.SubCodec`, wrapper constructors — matches byte-for-byte).
