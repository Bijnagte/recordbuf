# Gap ledger

This ledger records each construct the golden corpus cannot cover yet and each conformance scenario recordbuf does not satisfy, with the reason. A construct gap carries a `// GAP(<id>)` marker in a proto source (the vendored `test_messages_proto3.proto`, or a family proto under `fixtures/src/main/proto`) whose id matches its row here: the construct is commented out when it breaks generation or compilation, and left active (marker only, above a representative field) when it generates but is wrong in some format; a conformance-only row has no marker, because it is not a proto construct. `GapLedgerTest` fails when a marker has no row, when a construct row has no marker, or when an id appears twice. A conformance-only row must also be named by a `gap` row of the [conformance manifest](conformance-manifest.md), and a manifest `gap` row must name rows that exist here. Each gap closes in its own change (R16): uncomment the construct, fix the generator, add its goldens, and delete its row in that same change.

| id | construct or scenario | formats | kind | reason |
| --- | --- | --- | --- | --- |
| null-value-field | `google.protobuf.NullValue` fields: `TestAllTypesProto3.optional_null_value`, `oneof_null_value` | all | construct | The generator rejects the type at generation time (`well-known type google.protobuf.NullValue is not supported`; `DYNAMIC_UNSUPPORTED` in `WellKnownTypes`), which fails the whole file. |
| singular-wkt-default-present | A present-but-default singular `google.protobuf.Duration`, `Timestamp`, `FieldMask` or `Empty`: `optional_duration`, `optional_timestamp`, `optional_field_mask`, `optional_empty` | pb.hex, proto3.json | construct | A singular field of these types is non-null with the type's default (`Duration.ZERO`, `Instant.EPOCH`, `FieldMask.empty()`, `Empty.INSTANCE`) when absent, so the record cannot tell a present-but-default value from an unset one. The generated encoder skips it, while protobuf-java writes an empty message for a set field. The Interop converter follows the encoder (KTD7), so proto3 JSON omits the same values: conformance `EmptyFieldMask`, `TimestampEpochValue`, `TimestampZeroNormalized` and `TimestampHasZeroFractionalDigit` fail on it. Closing it needs presence tracking for these fields in the model. Repeated elements are not affected: the encoder writes every element, defaults included. The field is not commented out: it generates fine, and the marker is on `optional_duration` as the representative. |
| enum-unknown-number-map-value | A map whose enum value holds a number no constant has: `map_string_nested_enum`, `map_string_foreign_enum` | pb.hex, proto3.json | construct | A singular, repeated or oneof enum keeps such a number: it rides the record's unknown-field carrier (a varint under the enum field's number), which re-emits on encode and moves back into the protobuf-java field through Interop. A map entry has no field of its own to hold it, so the entry codec and the Interop converter still read an unknown map value through `forNumber`, which returns the first constant, and the number is lost. The field is not commented out: it generates fine, and the marker is on `map_string_nested_enum` as the representative. |
