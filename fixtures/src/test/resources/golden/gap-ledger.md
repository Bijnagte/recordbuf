# Gap ledger

This ledger records each construct the golden corpus cannot cover yet and each conformance scenario recordbuf does not satisfy, with the reason. A construct gap is commented out in the vendored `test_messages_proto3.proto` with a `// GAP(<id>)` marker whose id matches its row here; a conformance-only row has no marker, because it is not a proto construct. `GapLedgerTest` fails when a marker has no row, when a construct row has no marker, or when an id appears twice. Each gap closes in its own change (R16): uncomment the construct, fix the generator, add its goldens, and delete its row in that same change.

| id | construct or scenario | formats | kind | reason |
| --- | --- | --- | --- | --- |
| null-value-field | `google.protobuf.NullValue` fields: `TestAllTypesProto3.optional_null_value`, `oneof_null_value` | all | construct | The generator rejects the type at generation time (`well-known type google.protobuf.NullValue is not supported`; `DYNAMIC_UNSUPPORTED` in `WellKnownTypes`), which fails the whole file. |
| map-message-value | Map fields with a message value: `map_string_nested_message`, `map_string_foreign_message` | all | construct | The map codec only handles scalar keys and values; generation throws `wireScalar for typeUrl=<message type>`, which fails the whole file. |
| map-enum-value | Map fields with an enum value: `map_string_nested_enum`, `map_string_foreign_enum` | all | construct | Same map-codec limit as `map-message-value`: generation throws `wireScalar for typeUrl=<enum type>`. |
| map-bytes-value | Map field with a bytes value: `map_string_bytes` | all | construct | The generated map entry codec for `map<string, bytes>` does not compile: it declares `String value = CodecDefaults.int32()` and decodes `readBytes()` into it, and `toByteArray()` is called on `Object`. |
| enum-alias-name-collision | Aliased enum value `AliasedEnum.moo` (alias of `MOO`; `ALIAS_*`, `MOO` and `bAz` stay active) | all | construct | Enum constant names are upper-cased, so `moo` and `MOO` both become `MOO` and the generated enum fails with `variable MOO is already defined`. |
| nested-message-corecursive | `TestAllTypesProto3.NestedMessage.corecursive` (a `TestAllTypesProto3` field) | all | construct | `NestedMessage`'s Interop converter calls `TestAllTypesProto3.Interop`, which does not exist while `interop-all-types` is open, so the generated record does not compile. Close with `interop-all-types`. |
| interop-all-types | `(recordbuf.protobuf_java)` on `TestAllTypesProto3`, so no `TestAllTypesProto3.Interop` | proto3.json | construct | With the option, the generated Interop converter fails javac (84 errors). The to-do list for closing it: (1) WKT fields, singular and repeated, call `Boolean.Interop`, `Duration.Interop`, `Struct.Interop` and so on, which do not exist; (2) nested-enum fields (singular, repeated, packed, oneof, aliased) reference the reference enum as top-level `...proto3.NestedEnum` instead of `TestAllTypesProto3.NestedEnum`, and repeated enums call `getRepeatedNestedEnum()` without an index; (3) repeated bytes iterate the record's `Bytes` elements as `byte[]`, and the repeated or map bytes conversion to `ByteString` does not type-check; (4) edge field names map to getters that do not exist, for example `getFieldName4` versus the real getter; (5) the oneof message member calls a `getOneof_nested_message` getter that does not exist; (6) `NestedMessage.corecursive` needs `TestAllTypesProto3.Interop` (`nested-message-corecursive`). Closes only when the option can be re-enabled. Proto3 JSON is produced through Interop, so the format is not applicable to this message until then. |
| avro-surface | `(recordbuf.avro) = RECORDBUF_AVRO_ON` for the whole file (Avro is switched off for it) | avro.hex, avro.json | construct | The Avro option is file-level only, so every message in the file loses Avro, not just `TestAllTypesProto3`. With Avro on, the generated `TestAllTypesProto3AvroConverter` fails javac (60 errors). The to-do list for closing it: (1) enum-typed fields call `.value()` or `.name()` on the Avro `CharSequence` enum and import a bogus `TestAllTypesProto3.rec.NestedEnum`; (2) the oneof named `oneof_field` makes the converter call `getOneof_field()`, `setOneof_field()` and `oneof_field()`, none of which exist; (3) repeated WKT fields (wrappers, Duration, Timestamp, FieldMask, Struct, Any, Value, ListValue, Empty) are converted as scalars (`List<String>` versus `List<CharSequence>`, `String` versus `List<String>`); (4) singular Duration and bytes-wrapper members call getters that do not exist on the Avro side (`getSeconds()`, `getNano()`, `array()`, `toByteArray()`). Avro behavior of `recursive_message` and `NestedMessage.corecursive` stays unverified until then: the converter is emitted for the recursive message rather than falling back to `.avsc` only, and it is the converter that does not compile. |
| field-name-uppercase-start | Fields whose Java name starts upper-case: `_field_name3`, `FieldName8`, `Field_Name10`, `FIELD_NAME11`, `FIELD_name12`, `__field_name13`, `__Field_name14`, `Field_name18__` | all | construct | The generator turns each into a record component such as `FieldName3` or `FIELDNAME11`, which compiles but fails Checkstyle `MemberName` and `ParameterName` in the generated record. | oneof-snake-case-member | The whole `TestAllTypesProto3.oneof_field` oneof (nine active members, plus `oneof_null_value`, see `null-value-field`) | all | construct | Every member name is snake_case, so each generated member record (`Oneof_uint32Value`, `Oneof_nested_messageValue` and so on) fails Checkstyle `TypeName`.
