# Gap ledger

This ledger records each construct the golden corpus cannot cover yet and each conformance scenario recordbuf does not satisfy, with the reason. A construct gap carries a `// GAP(<id>)` marker in a proto source (the vendored `test_messages_proto3.proto`, or a family proto under `fixtures/src/main/proto`) whose id matches its row here: the construct is commented out when it breaks generation or compilation, and left active (marker only, above a representative field) when it generates but is wrong in some format; a conformance-only row has no marker, because it is not a proto construct. `GapLedgerTest` fails when a marker has no row, when a construct row has no marker, or when an id appears twice. A conformance-only row must also be named by a `gap` row of the [conformance manifest](conformance-manifest.md), and a manifest `gap` row must name rows that exist here. Each gap closes in its own change (R16): uncomment the construct, fix the generator, add its goldens, and delete its row in that same change.
